- (requirement) R1: A person with valid seeded Employee or Manager credentials signs in through one shared login and reaches the dashboard for the server-reported role (PRD FR-1; UX Foundation).
- (requirement) R2: An Employee submits inclusive start and end dates with a required trimmed 1-500 character reason; valid requests begin Pending (PRD FR-4).
- (requirement) R3: An Employee sees only their own request dates, reason, and Pending, Approved, or Rejected status, with no rejection reason (PRD FR-5).
- (requirement) R4: A Manager sees and retrieves only requests belonging to Employees assigned to that Manager (PRD FR-6).
- (requirement) R5: An assigned Manager decides a Pending request once as Approved or Rejected; no rejection reason is entered (PRD FR-7).
- (requirement) R6: Every protected API operation enforces authenticated role, request ownership, and persisted assignment server-side; browser-supplied identities do not grant access (PRD FR-3 and NFR-security; AD-1).
- (requirement) R7: The local Compose demo runs Next.js, Spring Boot, and PostgreSQL with one seeded Employee, one seeded Manager, and their assignment (AD-6 and Deployment & Operations Envelope).
- (constraint) C1: Use inclusive calendar-day ranges; start today or later, end on/after start, same-day allowed, no weekend/holiday rules; trim required reason and enforce 1-500 characters (PRD FR-4; AD-7).
- (constraint) C2: Session auth uses an HttpOnly cookie, CSRF on POSTs, GET /api/me for role selection, and Spring Boot server-side authorization; Next.js proxy is same-origin and transparent (AD-1 through AD-3; OpenAPI).
- (constraint) C3: Demo credentials remain local and outside the repository; persist BCrypt hashes only (PRD FR-1; AD-6).
- (constraint) C4: Every interactive control is keyboard operable with visible logical focus; after a Manager decision, focus moves to the updated Status and announces it (PRD NFR accessibility; UX Accessibility Floor; AD-8).
- (constraint) C5: No registration, Admin functionality, Keycloak, notifications, manager rejection reason, or production deployment in the first pass (PRD Non-Goals and MVP Boundaries).
- (event) Initiative requirements derived and self-checked against PRD, UX, architecture, and API contract; seven-story draft created for refinement review.
- (decision) 2026-11-13: Followed the user-specified six-story split and declined the separate PO refactor sweep; each story owns cleanup for its changes and no new behavior may enter through cleanup.
- (event) Story acceptance criteria drafted and expanded with per-story API authorization checks; a self-dependency found during status validation was corrected.
